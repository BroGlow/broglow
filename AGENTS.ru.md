# BroGlow — точки входа для агента

[English](AGENTS.md) | [Русский](AGENTS.ru.md)

BroGlow объединяет CLI, настольное приложение, прошивку ESP32-C3 SuperMini
и печатный корпус для работы с локальными coding-агентами. Описывайте
возможности и поддерживаемое оборудование прямо. Укажите исходный ClawLight
в README и сохраните лицензионные уведомления. BroGlow — отдельное приложение
с новыми идентификаторами и состоянием: без старых псевдонимов, миграций
и чтения старых ключей. Защищайте посторонние настройки и хуки пользователя.

Для **установки, обновления, подключения лампы или проверки службы Mac** сначала
прочитайте [руководство для агента](site/guide/ru/hardware.md#agent-runbook).
Оно направляет к процедурам установки готового пакета, сборки из исходников,
сопряжения по USB и проверки службы. Используйте его как единственный источник
рабочих команд и критериев завершения.

Для **изменений исходников, сборки или тестов** также прочитайте
[CLAUDE.ru.md](CLAUDE.ru.md). Работайте из корня этого репозитория. Сохраняйте
существующие изменения пользователя и историю Git.

**Генерируемые файлы — правило для любых изменений:** STL, STEP/STP и ZIP в любых
каталогах и независимо от регистра имени должны оставаться неотслеживаемыми
и игнорируемыми. Сохраняйте их правила `.gitignore`; не добавляйте эти файлы
принудительно или через Git LFS. Храните в Git редактируемые исходники и проверенные
свидетельства валидации; распространяйте результаты генерации как файлы релиза
с контрольными суммами. После генерации проверяйте пути результатов командой
`git check-ignore`; перед коммитом запускайте
`uv run --frozen python scripts/check-generated-artifacts.py`.

Весь каталог `models/broglow/preview/` должен оставаться игнорируемым и
неотслеживаемым, включая рендеры, размерные схемы и задания рендера. Храните в Git
выбранные ресурсы приложения/сайта и проверенные данные валидации.

Для **генерации корпуса, упаковки релиза, распространения или публикации сайта**
следуйте [руководству по выпуску](site/guide/ru/releasing.md) и его процедуре ручной
генерации или генерации агентом. Создавайте файлы корпуса в игнорируемом
`dist/enclosure/`. Архивы исходников GitHub содержат исходники
и инструкции; готовые файлы печати скачиваются отдельным комплектом корпуса из релиза.

Для **изображений, снимков экрана и других медиа** используйте только наши
материалы и следуйте [правилам медиа](site/guide/ru/media.md).
Точно подписывайте CAD-рендеры и используйте текущие исходники, а не старые пакеты.

Для **резервных копий и результатов проверок** используйте игнорируемую папку
`.recovery/` и следуйте
[правилам локального восстановления](site/guide/ru/hardware.md#local-recovery-files).

Готовый пакет содержит `BUILD.json` и `bin/broglow`, рабочая копия исходников —
`Cargo.toml` и `src/`. Выбирайте соответствующий способ установки. Просьба
установить приложение или подключить лампу не означает разрешения опубликовать
релиз или перепрошить работающую плату.

При **изменении руководства по оборудованию, настройки, проводки, управления
или поведения статусов** в том же изменении следуйте
[правилам поддержки документации сайта](site/README.ru.md#keep-the-instructions-in-sync).
Синхронизируйте английскую и русскую версии каждого руководства и документа
для разработчиков. Сайт включает исходник соответствующего языка; сохраняйте
одинаковые ID разделов, команды и технические значения в переводах. Запустите
`uv run --frozen --only-group docs python site/check-translations.py`,
затем соберите и проверьте локальную документацию и вариант Pages перед
завершением. Лицензионные тексты зависимостей сохраняются дословно.

При **редактировании YAML** используйте во всём проекте списки в блочном
формате: один элемент на строку, включая `needs` и матрицы workflow.
Массивы в одну строку не соответствуют нашему стилю.
