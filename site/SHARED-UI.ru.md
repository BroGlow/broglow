# Один интерфейс приложения, два хоста

Настольное приложение и демо главной страницы используют одни исходники интерфейса
из `assets/popover/`. Зависимостей от Vue и React нет; отдельной копии всплывающего
интерфейса тоже нет. Лендинг написан на статических HTML/CSS/JavaScript. Команды
предпросмотра, сборки и проверки — в [инструкции по сайту](README.ru.md#build-and-preview).

<a name="sources"></a>
## Общие исходники

| Исходник | Назначение |
| --- | --- |
| `assets/popover.html` | Общая оболочка документа и явные слоты инициализации |
| `assets/popover/popover.css` | Стили приложения |
| `assets/popover/popover.js` | Сессии, настройки, сведения о лампе и использование по агентам |
| `assets/popover/presentation.js` | Значки агентов, форматирование токенов и показатели строки меню в браузере |
| `assets/popover/document.js` | Сборка документа в браузере/Node с проверкой обязательных слотов |

<a name="hosts"></a>
## Границы хостов

Нативный хост встраивает оболочку, стили и скрипты при компиляции в `src/popover.rs`.
Он предоставляет `window.ipc.postMessage` и передаёт нативное состояние через
`window.__setState`. Имена обратных вызовов ошибок и подтверждений сохранены.
Установленному приложению не нужны внешние файлы или HTTP-сервер.

Хост лендинга в `site/app-preview.js` загружает те же исходники и передаёт
пример состояния и имитацию IPC через явный слот хоста. Изолированный iframe
разрешает только скрипты, не имеет нативных служб и доступа к документу родителя.
Оба направления сообщений проверяют источник, origin и токен канала конкретной
загрузки. Использование, удаление сессий и настройки в демо остаются только в памяти.

<a name="tracking"></a>
## Учёт использования

Изначально учёт выключен. Включите **Track usage** в Settings: появятся отдельные
квоты Claude и Codex, строка opencode только с токенами и общая сумма токенов
всех агентов. Это демонстрационные значения. **Show usage in menu bar** скрывает
только показатели строки меню, сохраняя учёт и итоги во всплывающем окне.
Выключение учёта тоже скрывает эти показатели; предпочтение их показа сохраняется
до следующего включения.

<a name="packaging"></a>
## Статическая сборка и проверки

`site/pages.py` упаковывает основную страницу, руководство, общий интерфейс и
закреплённые браузерные зависимости в игнорируемую `site/_pages/`. При просмотре
исходников лендинг загружает `../assets/`; сборщик копирует нативную оболочку,
отрисовщик и значки трея в `app-ui/` и меняет пути, сохраняя байты общих исходников.
Артефакт работает без репозитория. Отдельного сборщика прототипа больше нет.

После правок общих исходников повторите сборку. Тесты нативного интерфейса проверяют
те же собранные представления, что и демо; Pages CI запускает их при изменениях
общих исходников. Выполните `node --test site/*.test.cjs` и
`node --test tests/js/lamp-status.test.mjs tests/js/popover-library.test.mjs`.
Сборка для публикации и границы проверок описаны в
[инструкции по сайту](README.ru.md#check-the-exact-pages-artifact-locally).
Сборка не публикует сайт.
