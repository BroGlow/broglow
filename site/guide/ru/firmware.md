# Протокол прошивки и диагностика

Для установки, подключения проводов и обычной работы используйте
[руководство по настройке](hardware.md).
Этот справочник описывает прошивку C3 и протокол связи с компьютером.

<a name="pairing-feedback-and-diagnostics-without-external-leds"></a>

## Индикация сопряжения и диагностика без внешних светодиодов

Три внешних светодиода показывают описанные ниже сигналы. Настроенный встроенный
светодиод — одноцветный, на GPIO8, с активным низким уровнем; он кодирует цвета
сессий числом импульсов, а не сменой цвета. Светодиод описан в
[руководстве производителя SuperMini](https://www.nologo.tech/en/product/esp32/esp32c3SuperMini/esp32C3SuperMini.html),
а [справочник Apache NuttX для SuperMini](https://nuttx.apache.org/docs/latest/platforms/risc-v/esp32c3/boards/esp32c3-supermini/index.html)
описывает полярность GPIO8 и его роль при выборе режима загрузки. Варианты плат
различаются: эта сборка не определяет, установлен ли светодиод. Отдельным
индикатором питания прошивка не управляет. Текущие ограничения проверок
указаны в руководстве по эксплуатации. GPIO8 управляется только после
обычной загрузки; не добавляйте внешнюю цепь, которая тянет этот вывод
выбора режима загрузки к низкому уровню при сбросе.

| Режим / условие | Внешние красный/жёлтый/зелёный светодиоды | Встроенный светодиод |
| --- | --- | --- |
| `startup`: первые три секунды после инициализации прошивки | Все три плавно загораются и гаснут вместе: два цикла по 1,5 секунды | Такие же изменения яркости с максимумом 32/255 |
| `preview`: ползунок яркости подключённой лампы | Все три непрерывно светят с выбранным процентом яркости; возврат к статусу через две секунды после последней пробы | Тот же процент яркости применяется к базовому уровню 32/255 |
| `identify`: Identify на подключённой лампе | Красный → жёлтый → зелёный три раза, по одному светодиоду, 100 мс на LED (всего 0,9 секунды); приложение запрашивает 100% | Один импульс 40 мс на шаг при 32/255, масштабированный запрошенным процентом |
| `connected`: первая корректная зашифрованная запись каждого BLE-соединения, включая `N` | Все три включаются один раз на 250 мс | Включается на те же 250 мс с яркостью 32/255 |
| `status`: свежий `R`, `Y` или `G` | Соответствующий светодиод горит постоянно | Повторяющиеся группы: зелёный — один, жёлтый — два, красный — три импульса по 100 мс с интервалом 250 мс; одна группа каждые три секунды при 32/255 |
| `status`: свежий `N` | Выключены | Выключен |
| `pairing`: окно открыто, свежего статуса нет | Красный → жёлтый → зелёный, по 250 мс на шаг | Один импульс 100 мс на шаг при 32/255 |
| `unpaired`: на плате нет ключей сопряжения, окно закрыто, свежего статуса нет | Все три одну секунду включены, одну выключены | Тот же ритм при 32/255 |
| `waiting`: на плате есть ключи сопряжения, BLE отключён, окно закрыто, свежего статуса нет | Все три дают импульс 100 мс при 8/255 каждые 30 секунд; первый — через 30 секунд в этом режиме | Такой же слабый импульс |
| `stale`: BLE остаётся подключённым после истечения срока подтверждённого статуса | Выключены | Выключен |

Значения заполнения выше указаны при **100% яркости лампы**. Сохранённая
настройка масштабирует все управляемые выходы, включая индикацию запуска,
подключения и тихого ожидания; проба временно использует процент ползунка,
а Identify — запрошенный процент (100% из приложения).
При 0% выбранный уровень не светится; красный индикатор питания платы не
меняется. См. [управление яркостью](hardware.md#brightness-control).

Плавная индикация запуска имеет приоритет в течение своих трёх секунд,
а обработка статуса и сопряжения продолжается в фоне. Она запускается один
раз при загрузке и заканчивается автоматически. После неё явная проба
яркости или анимация Identify временно имеет приоритет над обычным статусом и подтверждением
подключения; отключение, потеря аутентификации или устаревание статуса
отменяют пробу. В остальных случаях одиночная вспышка подключения имеет
приоритет на 250 мс; последующие корректные записи `N`/`R`/`Y`/`G` обновляют
сохранённый статус, не отменяя и не перезапуская вспышку. Отключение, потеря
аутентификации или истечение срока статуса отменяют её; даже задержанная
первая запись не может продлить свечение за десятисекундный срок устаревания.
В остальных случаях свежий статус, включая последовательные команды и `N`,
имеет приоритет над индикацией настройки и ожидания. Подтверждённое
BLE-соединение с просроченным статусом остаётся тёмным, даже если окно
сопряжения ещё открыто. Эти сигналы не меняют однобайтовый протокол или
десятисекундный тайм-аут статуса.

Выходы используют восьмибитный PWM с частотой 2 кГц. В `platformio.ini`
`BUILTIN_LED_PIN=8` и `BUILTIN_LED_ACTIVE_LOW=1` выбирают обычный встроенный
светодиод; установите номер вывода `-1`, чтобы отключить этот выход на другой
плате. `BUILTIN_LED_BRIGHTNESS=32` задаёт обычные импульсы встроенного
светодиода, а `WAIT_LED_BRIGHTNESS=8` — слабые импульсы ожидания на всех
четырёх выходах до применения рабочего процента яркости.
Установите `WAIT_LED_BRIGHTNESS=0`, чтобы отключить эти слабые импульсы.
После изменения параметров пересоберите прошивку и запишите её на
идентифицированную плату; значения PWM — заданные уровни заполнения,
а не измеренная яркость.

При подключённом последовательном USB-интерфейсе прошивка сообщает
`pairing=open duration_ms=60000`, `pairing=closed`, `authentication=ok`
или код ошибки. Запрос `?\n` возвращает диагностическую строку.
Эта диагностика только читает состояние и доступна, когда лампой управляет
BLE; последовательные команды установки светодиодов по-прежнему
игнорируются до отключения BLE.

Используйте только идентифицированный `BOARD_PORT`; сначала закройте
остальные мониторы последовательного порта:

```bash
~/.platformio/penv/bin/python - "$BOARD_PORT" <<'PY'
import sys
import time
import serial

with serial.Serial(sys.argv[1], 115200, timeout=0.5, write_timeout=2) as port:
    port.rts = False
    port.dtr = True
    time.sleep(0.3)
    port.reset_input_buffer()
    port.write(b"?\n")
    port.flush()
    until = time.monotonic() + 3
    while time.monotonic() < until:
        line = port.readline().decode(errors="replace").strip()
        if line:
            print(line)
        if line.startswith("state="):
            break
PY
```

Строка сообщает сохранённое состояние сессии `state`, заданные флаги
включения `red/yellow/green`, `owner`, `connected`, `authenticated`,
`pairing`, `bonds`, `age_ms` и число принятых корректных статусов `accepted`.
Она также сообщает `mode`, `red_pwm`, `yellow_pwm`, `green_pwm`,
`builtin_pwm`, `builtin_pin` и `brightness` (процент, сохранённый платой в RAM).
При `mode=preview` или `mode=identify` заполнение использует временный запрошенный процент; поле
`brightness` и сохранённое состояние сессии `state` продолжают описывать
основные настройки. Флаги включения означают, что заданное заполнение PWM
ненулевое; это не чтение цифрового состояния выводов. Значения PWM —
заполнение включённого света 0..255 после масштабирования яркости и до
инверсии активного низкого уровня встроенного светодиода. Поэтому `state=N`
может сочетаться с ненулевым заполнением при запуске, пробе, Identify, настройке
или индикации подключения. `authenticated=1` означает, что BLE-соединение
получило зашифрованный доступ; `age_ms` и `accepted` помогают проверить
доставку обновлений раз в две секунды. Ничто из этого не подтверждает
исправность цепи светодиода, ток или видимый свет. После диагностики
перейдите на питание только от блока, если проверяете работу без
USB-соединения для данных.

Для настройки точная команда `INFO\n` (или CRLF) возвращает идентификатор,
не меняя сопряжение, светодиоды или состояние тайм-аута. `PAIR\n` открывает
или продлевает окно и возвращает тот же идентификатор; она не удаляет ключи
сопряжения и не отключает текущее центральное устройство. CLI отправляет
`INFO` перед `PAIR`. Пример ответа (идентификатор зависит от платы):

```text
broglow_pair identity=001122334455 service=7d2ea28a-f7bd-485a-bd9d-92ad6ecfe93e
```

Эти команды настройки работают и при управлении светодиодами через BLE;
произвольные последовательные команды цвета по-прежнему не перехватывают
управление. Объявляемый идентификатор — шесть байтов базового MAC, а не
потенциально меняющийся приватный Bluetooth-адрес в эфире.

<a name="ble-contract-and-firmware-behavior"></a>

## Контракт BLE и поведение прошивки

| Параметр | Значение |
| --- | --- |
| Имя | `BroGlow C3` и суффикс платы из четырёх шестнадцатеричных цифр |
| UUID сервиса | `7d2ea28a-f7bd-485a-bd9d-92ad6ecfe93e` |
| Характеристика записи статуса | `7d2ea28b-f7bd-485a-bd9d-92ad6ecfe93e` |
| Характеристика записи яркости | `7d2ea28c-f7bd-485a-bd9d-92ad6ecfe93e` |
| Операция GATT | Запись с ответом |
| Данные статуса | Ровно один ASCII-байт: `R`, `Y`, `G` или `N`; без перевода строки |
| Данные яркости | Ровно один бинарный байт, процент 0..100; не ASCII-цифры. По умолчанию на плате 100; значение сбрасывается при перезапуске. |
| Данные пробы | В той же зашифрованной характеристике яркости: два бинарных байта `[percent, 1]`, где percent — 0..100. Временно переопределяет все управляемые источники света на две секунды с момента получения; сохранённую яркость не меняет. |
| Данные Identify | В той же зашифрованной характеристике яркости: два бинарных байта `[percent, 2]`, где percent — 0..100. Три прохода красный → жёлтый → зелёный по 100 мс на LED (0,9 секунды с момента получения), затем возврат последнего статуса и сохранённой яркости. Приложение отправляет `[100, 2]`; настройки не меняются. |
| Период обновлений компьютера | Две секунды |
| Тайм-аут устаревания платы | Десять секунд с последнего корректного статуса; сбрасывает цвет сессии, затем [индикация](#pairing-feedback-and-diagnostics-without-external-leds) следует состоянию соединения и сопряжений |
| Владение управлением | Подключённый BLE-клиент; последовательный порт — только при отключённом BLE |
| Безопасность | Сопряжение LE Secure Connections Just Works; обе характеристики записи требуют шифрования. Новое сопряжение допускается только при открытом окне настройки. |

После обнаружения компьютер записывает яркость до начальной записи `N` или
статуса, поэтому поддерживаемая прошивка использует сохранённый уровень
для первой индикации подключения. Последующие изменения процента
передаются через существующее соединение. Если характеристики яркости нет,
компьютер сохраняет прежнюю передачу только статуса и сообщает об отсутствии
этой возможности.

Интерфейс ограничивает частоту изменений пробы ползунком примерно одним за 80 мс
и обновляет удерживаемый указатель каждые 500 мс. Identify отправляет один запрос
для выбранной подключённой лампы. Компьютер хранит только последнее событие для
конкретной лампы (или запроса ко всем лампам) в течение двух секунд как для пробы
ползунком, так и для Identify. Каждое соединение использует более новое
подходящее событие для конкретной лампы или всех ламп; адресный запрос не может
повлиять на другую лампу. Последний запрос пробы или Identify заменяет предыдущий.
Обычные обновления статуса не продлевают ни один из режимов.
Прошивка требует подтверждённого аутентифицированного соединения и свежего
статуса; просроченный запрос или запрос от предыдущего соединения отбрасывается.

Старая прошивка молча игнорирует `[percent, 2]`, даже если подтверждает запись
и поддерживает пробу ползунком. Для анимации нужна соответствующая прошивка;
обновление приложения не прошивает плату. Используйте штатную процедуру копии/записи
для определённой платы из руководства по настройке.

Пустые и многобайтовые данные **статуса**, неизвестные байты статуса, яркость
выше 100 и данные яркости, отличные от одного байта, `[percent, 1]` или `[percent, 2]`,
игнорируются. Яркость, проба и Identify не обновляют тайм-аут статуса. Ответ
стека GATT на запись подтверждает получение; это не специальный ответ
о проверке данных приложением и не доказательство работы электрической
цепи светодиодов. Все изменения GPIO и решения о тайм-аутах выполняются
в основном цикле; обработчики передают состояние через синхронизированные
почтовые ящики FreeRTOS. Тайм-аут использует беззнаковую арифметику времени,
устойчивую к переполнению. Отключение возобновляет BLE-объявления.

<a name="gatt-cache-after-a-firmware-upgrade"></a>

### Кеш GATT после обновления прошивки

После добавления атрибута яркости сопряжённый Mac может продолжить
использовать кеш сервиса, содержащий только статус. Прошивка запрашивает
индикацию Service Changed для подключающегося устройства из
`ESP_GATTS_CONNECT_EVT` через `BLEDevice::setCustomGattsHandler`
и публичный API
`esp_ble_gatts_send_service_change_indication(gatts_if, remote_bda)`.
Это должно вызвать повторное обнаружение с сохранением существующего
сопряжения. [API Espressif GATTS](https://docs.espressif.com/projects/esp-idf/en/v4.4.7/esp32/api-reference/bluetooth/esp_gatts.html),
[отправка индикации и установка режима в IDF 4.4.7](https://raw.githubusercontent.com/espressif/esp-idf/v4.4.7/components/bt/host/bluedroid/bta/gatt/bta_gatts_api.c).

SDK в закреплённой Arduino 2.0.17 по умолчанию использует автоматический
режим Service Changed, который отклоняет этот явный запрос. Поэтому при
запуске выбирается ручной режим через `BTA_GATTS_SetServiceChangeMode(1)`.
Его сигнатура с `uint8_t` проверена в исходниках IDF 4.4.7, а экспорт —
в фактической библиотеке C3 `libbt.a`; это зависимость данного закреплённого
SDK, а не переносимый Arduino API. Перед сменой инструментов сборки
перепроверьте экспортируемый символ, его сигнатуру, значение ручного режима
и поведение обработчика, затем повторите проверку обновления прошивки
с сохранённым сопряжением. Поставленная в очередь индикация сама по себе
не доказывает обновление кеша macOS. Проверенное обновление сопряжённых
Mac и C3 прошло повторное обнаружение и передачу яркости без удаления
лампы или повторного сопряжения. Не удаляйте ключи сопряжения как обычный
шаг обновления для поддержки яркости.
