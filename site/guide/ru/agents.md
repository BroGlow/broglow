# Подключите coding-агентов

`broglow install` регистрирует хуки или плагин для поддерживаемых агентов,
которых найдёт на этом компьютере. Сессии T3 Code обнаруживаются автоматически без хуков. Только Codex просит вас их
подтвердить. Доказательство, что агент подключён, — смена статуса в списке сессий
BroGlow, а не горящая лампа.

| Агент | Что делает `broglow install` | Что делаете вы |
| --- | --- | --- |
| Claude Code | Добавляет хуки в `~/.claude/settings.json`. | Ничего; открытые сессии сообщают статус со следующего запроса. |
| Codex | Добавляет хуки в `$CODEX_HOME/hooks.json` (по умолчанию `~/.codex`). | [Разрешите их в `/hooks`](#codex-setup). |
| opencode | Устанавливает плагин `~/.config/opencode/plugins/broglow.js`. | Перезапустите работающие сессии. |
| GitHub Copilot CLI | Записывает `~/.copilot/hooks/broglow.json`. | Перезапустите сессии, открытые во время установки. |
| T3 Code | Читает локальное состояние v2 и уже связанные машины; не меняет настройки T3. | Откройте T3 Code 0.1 или новее; см. [T3 Code](#t3-code-setup). |

Установили агента после BroGlow? Снова выполните `broglow install`.

BroGlow читает локальное состояние агентов и по умолчанию отслеживает уже связанные
машины T3; охват T3 Code и способ отключения описаны ниже. Обычные чаты ChatGPT и
облачные задачи вне этих источников не собираются. Возврат к сессии,
названия и скрытие одинаковы для всех агентов: [Работа с сессиями](sessions.md).

<a name="usage"></a>

## Расход по агентам

Включите **Settings → Track usage** в поповере строки меню. По умолчанию учёт
выключен. Claude, Codex и opencode показывают отдельные суммы токенов за сегодня;
**All agents today** складывает эти локальные суммы. BroGlow не рассчитывает
стоимость токенов и не оценивает счета. Это объём локальной работы, а не остаток
подписки.
В поповере эти суммы собраны под одним заголовком **Usage**, а ниже показаны имена агентов с их монохромными иконками из приложения.

| Агент | Токены за сегодня | Лимиты |
| --- | --- | --- |
| Claude Code | Локальные транскрипты Claude. | OAuth endpoint расхода Claude, если доступен. |
| Codex | Локальные записи rollout Codex. | Последние лимиты из этих записей, если доступны; они могут отставать от расхода аккаунта. |
| opencode | Завершённые сообщения ассистента, полученные плагином BroGlow после включения учёта. | Из токенов не выводятся лимиты подписки. |
| GitHub Copilot CLI | Учёт токенов недоступен. | Недоступны. |
| T3 Code | Отдельной суммы нет; локально записанный расход остаётся в сумме Claude, Codex или opencode. | Отдельные лимиты T3 не вычисляются. |

Лимиты Claude и Codex независимы: BroGlow подписывает каждый источник и никогда
не складывает их проценты. Недельный лимит может показываться отдельно. Отсутствующие
лимиты скрыты, а не показаны как нулевые. На macOS рядом с каждым доступным
процентом в строке меню стоит монохромная иконка Claude или Codex из приложения;
без лимитов показывается общая локальная сумма токенов. В Windows имена агентов
показываются во всплывающей подсказке значка в трее.

**Show usage in menu bar**, сразу под **Track usage**, по умолчанию включён.
Выключите его, чтобы скрыть числа расхода и иконки агентов рядом с индикатором
статуса; фоновый учёт и суммы в поповере продолжат работать. Переключатель
недоступен, пока учёт выключен, и сохраняет выбранный режим отображения.
В Windows он управляет расходом во всплывающей подсказке значка в трее.

Итоги Claude включают локальные транскрипты субагентов, а итоги Codex —
архивные чаты и исключают скопированную историю форков. Старые логи форков с
неоднозначным владельцем могут не учитываться, чтобы не считать унаследованный
расход повторно. Лимиты Codex — последние наблюдавшиеся значения аккаунта,
а не запрос к аккаунту в реальном времени.

opencode с API-ключом добавляет только локально полученные токены. Расход через API
не уменьшает лимит вашей подписки Claude или Codex. После обновления BroGlow
выполните `broglow install`, чтобы обновить плагин opencode, и перезапустите opencode.
BroGlow не импортирует прежний расход opencode: учитываются только сообщения,
полученные обновлённым плагином после включения учёта.

<a name="t3-code-setup"></a>

## T3 Code

T3 Code **0.1 или новее** с базой состояния v2 отслеживается автоматически для всех
его провайдеров. BroGlow читает `userdata/statev2.sqlite` и базу сборки для разработки
`dev/statev2.sqlite` в `~/.t3`.
Для другого расположения задайте `T3CODE_HOME` процессу BroGlow, указав домашний
каталог T3; явно заданный каталог выбирает только базу `userdata`. Старая база до v2
не поддерживается. BroGlow не меняет настройки T3, не устанавливает хуки и не пишет
в его базу.

1. Откройте T3 Code и отправьте запрос в видимом неархивном треде.
2. Убедитесь, что тред появился в BroGlow с подписью **T3 Code**: **Working** во время
   хода, **Needs help** при блокирующем запросе разрешения или вопросе и **Paused** после ответа
   или прерывания. Открытый список сессий обновляется в течение пяти секунд.
3. На macOS нажмите строку, чтобы вернуться именно к этому треду в соответствующем приложении T3.

Названия и проекты берутся из самого T3; рабочее дерево треда имеет приоритет перед
директорией проекта. Архивные или удалённые треды/проекты, скрытые субагенты и
побочные чаты не влияют на лампу. Ожидающая фоновая работа сохраняет рабочий статус
родительского треда; автоматическое сжатие истории в простое не возвращает скрытый
тред. Локальные ссылки на сессии провайдера убирают дубли строк Claude/Codex/opencode
после использования треда провайдера в T3. Локально сам импорт или открытие истории не
скрывает её исходную строку и не считается текущей работой T3. Продолжение
разговора через T3 делает его сессией T3.
После выхода локального сервера T3 его треды перестают влиять на текущий статус.

Хуки Claude/Codex отдельно распознают продолжение сессии в обычном CLI. Общий
SDK-сервер OpenCode не передаёт таких сведений: продолжение в обычном CLI может
оставаться представленным строкой T3, пока его сервер работает.

<a name="t3-linked-machines"></a>

### Связанные машины

**Уже связанные peer-машины отслеживаются по умолчанию.** BroGlow читает существующие
связи T3, которые соблюдают ограничения доступа связанного агента, и использует их
учётные данные для MCP-инструментов чтения проектов и тредов. Одного сохранённого
SSH-подключения в настольном приложении недостаточно. Сначала создайте в T3 связь
с машиной только для чтения; BroGlow не связывает новые машины и не запускает
удалённые задачи. Опрос работает
в фоне, поэтому недоступная машина не блокирует локальные обновления. Чтобы отключить
его, добавьте поле в существующий `~/.broglow/config.json` (или
`$BROGLOW_HOME/config.json`), сохранив остальные поля:

```json
{
  "t3_linked_machines_enabled": false
}
```

Задайте `true` или удалите поле, чтобы вернуть наблюдение. BroGlow не читает
зашифрованный каталог подключений настольного приложения.

Если T3 отклоняет связь, потому что удалённая версия не может соблюдать ограничения
связанного агента, обновите **удалённый сервер T3** до совместимой версии T3 Code,
перезапустите его и повторите связывание. Обновление BroGlow или только локального
приложения T3 не обновляет этот сервер. BroGlow требует от удалённого сервера
поддержки ограничений доступа и защиты связи (link fence) и не обходит эту проверку.

Удалённые MCP-данные менее подробны, чем локальная
база: ожидающие разрешения и вопросы консервативно дают **Needs help**, а ссылки на
сессии провайдеров, часть фоновых задач и активность наблюдения за PR недоступны.
Поэтому дубли удалённых сессий провайдеров не всегда можно убрать. Импортированная
история исключается при наличии известного признака импорта в MCP; ручной импорт
без такого признака на удалённой машине всё ещё может отображаться как сессия T3
на паузе. Расход остаётся
в существующих локальных суммах провайдеров, как описано [выше](#usage); удалённый
расход не добавляется.

<a name="codex-setup"></a>

## Codex

1. Откройте Codex CLI (0.144 или новее) в терминале. Для задач в приложении запускайте
   его от того же пользователя и с тем же `CODEX_HOME`, что и приложение, например
   встроенный `/Applications/ChatGPT.app/Contents/Resources/codex`.
2. Введите `/hooks`. Проверьте и разрешите восемь записей BroGlow: `SessionStart`,
   `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PermissionRequest`, `Stop`,
   `Interrupt` и `SessionEnd` (для последних двух нужна свежая версия Codex).
   Каждая подписана **BroGlow: update session status** и запускает
   `"/path/to/broglow" codex-hook`. Остальные хуки оставьте без изменений. После
   изменения хуков разрешение может потребоваться снова.
3. Отправьте запрос в новой локальной задаче Codex — в CLI или приложении.
   В списке сессий BroGlow проверьте, что эта задача показывает **Working** во время
   работы и **Paused** после ответа. Запрос ручного подтверждения или вопрос
   показывает **Needs help**. Неотвеченный асинхронный вопрос
   [истекает](sessions.md#question-expiry), когда Codex подтверждает завершение его хода.
   Автоматическая проверка разрешения сохраняет **Working**,
   если Codex записал проверяющего; иначе запросы разрешения показывают **Needs help**.
   Прерывание хода ставит его на паузу; завершённая сессия перестаёт влиять на текущий
   статус.

Ручные чаты `/side` показывают **Working** во время работы и **Needs help**, когда
нужен ваш ответ, не меняя статус исходного чата. После ответа они перестают влиять
на текущий статус, а не остаются на паузе. Обычные сохранённые ветки чатов
по-прежнему показывают **Paused** после ответа.

Ложный красный при проверке разрешений в `/side` описан на странице [«Известные проблемы»](known-issues.md#codex-side-approval).

Несохранённые фоновые запуски, внутренние субагенты, проверяющие разрешений и
временные помощники для подготовки предложений приложения не появляются
отдельными чатами и не влияют на лампу. Действия субагента не сбрасывают
неотвеченный вопрос родительского чата и не меняют его статус. Сохранённые чаты
задач по расписанию, самостоятельные чаты, созданные или ответвлённые агентом,
и принятые предложенные задачи продолжают отслеживаться, даже если их название
или запрос начинается с `This is an app-generated request`. BroGlow определяет
фоновую работу по метаданным сессии; одной этой фразы недостаточно.
Если старая неактуальная строка осталась без нужных метаданных, один раз
[скройте её](sessions.md#dismiss).

<a name="codex-missing-hooks"></a>

### Если записей BroGlow нет

Если вы установили Codex после BroGlow, снова выполните `broglow install` и откройте
`/hooks`.

Если Codex сообщает, что хуки отключены, сами включите `hooks = true` в разделе
`[features]` файла `config.toml` Codex. BroGlow этот файл никогда не меняет.

<a name="codex-no-session"></a>

### Если сессия не появилась

Задачам, уже открытым в боковой панели, нужен новый запрос. Если не помогло, завершите
активную работу, перезапустите Codex и попробуйте снова.
