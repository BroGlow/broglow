# Сайт ClawLight DIY

[English](README.md) | [Русский](README.ru.md)

Короткая главная страница написана на обычных HTML/CSS. Отдельное руководство
использует [MkDocs](https://www.mkdocs.org/) с
[Material](https://squidfunk.github.io/mkdocs-material/) и
[static-i18n](https://ultrabug.github.io/mkdocs-static-i18n/). Страницы описывают
приложение ClawLight, прошивку ESP32-C3 и печатный корпус.

<a name="edit-the-guide"></a>

## Редактирование руководства

Редактируйте обычные Markdown-файлы; сгенерированный HTML не редактируется
и не добавляется в коммиты.

| Тема | Английский | Русский |
| --- | --- | --- |
| Детали, модели и проводка | `guide/en/index.md` | `guide/ru/index.md` |
| Установка, запрос агенту и Bluetooth | `guide/en/installation.md` | `guide/ru/installation.md` |
| Интеграция Codex | `guide/en/codex.md` | `guide/ru/codex.md` |
| Решение проблем и запрос агенту | `guide/en/troubleshooting.md` | `guide/ru/troubleshooting.md` |
| Полное руководство по оборудованию | `../docs/hardware-setup.md` | `../docs/hardware-setup.ru.md` |
| Прошивка, релизы, изображения, проектирование корпуса | `../docs/NAME.md` | `../docs/NAME.ru.md` |
| Печать и сборка | `../models/clawlight/PRINT_GUIDE.en.md` | `../models/clawlight/PRINT_GUIDE.md` |

Навигация и настройки темы находятся в `mkdocs.yaml`. Чтобы добавить страницу,
создайте одноимённый файл в обеих языковых папках и добавьте его в `nav`,
а русский заголовок — в `nav_translations`. Запросы агенту оформляются
ограждёнными блоками `text`; кнопку копирования добавляет Material.
Для таблиц и ссылок используется обычный Markdown.

<a name="keep-the-instructions-in-sync"></a>

## Синхронизация инструкций

Поддерживайте полное руководство в **`docs/hardware-setup.md`** на английском
и **`docs/hardware-setup.ru.md`** на русском. Каждый языковой маршрут сайта
включает свой исходник через PyMdown Snippets. Страницы прошивки, выпуска,
медиа, корпуса и печати устроены так же; один язык не подменяется другим.
Те же Markdown-исходники доступны для чтения в репозитории и входят в пакеты.

Схема проводки и команды PATH в каждом кратком руководстве берутся из именованных
разделов полного руководства на том же языке, например:

```text
--8<-- "docs/hardware-setup.ru.md:lamp-wiring"
```

Сохраняйте маркеры `start:lamp-wiring` / `end:lamp-wiring`, `path-check` и
`path-setup` в обеих версиях. Переводите текст, комментарии и подписи схем;
сохраняйте эквивалентные команды, GPIO, номиналы резисторов и поля протокола.
Отсутствующий раздел останавливает сборку с ошибкой. У переведённых заголовков
должны быть те же явные ID разделов, что и у оригиналов: закладки и переключение
языка тогда остаются в том же разделе.

У каждого написанного для проекта документа есть английская и русская версии,
включая инструкции репозитория и руководства в пакетах. `check-translations.py`
проверяет наличие пар файлов, якоря заголовков и источники включаемых страниц;
страницы с подстановкой английского текста вместо перевода не допускаются.
Лицензионные уведомления зависимостей сохраняйте дословно.

При изменении поведения в том же изменении проверьте затронутые краткие
пояснения и запросы агенту **в обеих папках** `guide/en/` и `guide/ru/`.
Эти сводки редактируются человеком или coding-агентом, а не переводятся
автоматически. `AGENTS.md` направляет будущую работу с кодом сюда, чтобы
пользователю не приходилось переносить изменения между сессиями. Перед
коммитом выполните проверки ниже и сборку Pages.

Изменения сайта или документации запускают workflow Website, включая проверки
PR. После включения Pages отправка в `main` автоматически пересобирает
опубликованное руководство. Локально `mkdocs serve` наблюдает за исходниками
руководства; для полного статического просмотра после правок повторите
документированную команду сборки.

<a name="build-and-preview"></a>

## Сборка и предварительный просмотр

Выполняйте команды из **корня репозитория clawlight**. В CI используется
Python 3.14; он также проверен локально.

```bash
python3 -m venv site/.venv
site/.venv/bin/python -m pip install -r site/requirements-docs.txt
site/.venv/bin/mkdocs build --strict -f site/mkdocs.yaml
python3 -m http.server 8080 --bind 127.0.0.1
```

Откройте http://127.0.0.1:8080/site/ для главной страницы и
http://127.0.0.1:8080/site/docs/ для руководства. После редактирования Markdown
повторите сборку и обновите страницу. Результат сборки руководства игнорируется
в `site/docs/`; сборка никогда не очищает главную страницу. Зависимости
изолированы в `site/.venv/` и закреплены на совместимых версиях MkDocs 1.x
и Material.

Для редактирования документации с автоматическим обновлением используйте
`site/.venv/bin/mkdocs serve -f site/mkdocs.yaml`. Этот сервер обслуживает
только документацию, без главной страницы и внешних скачиваемых файлов;
для полного сайта используйте описанный выше просмотр из корня репозитория.

<a name="interactive-3d-and-ar"></a>

## Интерактивная 3D-модель и AR

Главный блок сначала показывает статичный рендер кандидата корпуса к выпуску
1.0.0. Кнопка **«Посмотреть в 3D»** загружает локальный модуль
`@google/model-viewer` 4.3.1 из `vendor/` и нашу `assets/clawlight.glb`.
До нажатия ни модель, ни рендерер не загружаются. Без JavaScript или после
ошибки модуля/модели изображение остаётся доступным. Перетаскивание, жест
масштабирования, колесо мыши, стрелки и Page Up/Page Down используют управление
камерой компонента; «Сбросить вид» возвращает исходную камеру. Автоматического
вращения и собственного рендерера нет.

AR использует режимы компонента `webxr`, `scene-viewer` и `quick-look` с
`ar-scale="fixed"`. GLB экспортируется в метрах и не требует масштабирования
в HTML. `ios-src` намеренно отсутствует: Safari на iPhone/iPad создаёт USDZ
по запросу. Работа в других браузерах iOS не обещается. Для WebXR нужен HTTPS;
loopback достаточен для разработки, но телефон не может загрузить модель
с localhost другого устройства. Компонент показывает кнопку AR только
на поддерживаемых устройствах. Это
[официальное поведение AR](https://modelviewer.dev/examples/augmentedreality/);
размещение и размер на настоящих телефонах ещё требуют приёмочных проверок.

`assets/clawlight-model.json` фиксирует исходники модели и её габариты. Это
наш кандидат корпуса к выпуску, включая иллюстративную электронику.
Интерактивный экспорт нужен для просмотра; печатные CAD и STL находятся
в отдельном архиве корпуса. Сохраняйте формулировку кандидата к выпуску
в обоих языках и отмечайте финальные физические проверки отдельно от
готовности релиза. GLB и метаданные принадлежат экспортёру: не редактируйте
сгенерированную геометрию в сайте. Для повторного экспорта из полной рабочей
копии активируйте Python-окружение CAD и выполните:

```bash
python -m pip install -r models/clawlight/requirements.txt
python scripts/export-web-model.py
python scripts/export-web-model.py --check
```

Для экспорта нужен установленный CAD-скилл в `~/.agents/skills/cad`; если
он находится в другом месте, передайте `--cad-skill /path/to/cad`. Исходная
модель не меняется. `--check` использует только стандартную библиотеку Python:
проверяет сохранённый в репозитории GLB и его происхождение, а при наличии
дерева CAD — каждый записанный хеш исходника. В сокращённом экспорте исходников
без CAD он явно пропускает недоступные сравнения. Обычный архив исходников
1.0.0 включает нашу CAD-модель. CI сайта запускает эту проверку. Обычные
сборки сайта используют GLB из репозитория и не требуют CAD-библиотек.
Не используйте сжатие Draco/KTX, если эти необязательные кодеки также не
размещены локально. `vendor/README.md` фиксирует источник закреплённой версии,
целостность и лицензию. Сборка Pages копирует `assets/`, `vendor/` и
`model-preview.js`; проверка ссылок охватывает URL модели, модуля и постера.

<a name="languages-and-behavior"></a>

## Языки и поведение

Обе страницы выбирают первый поддерживаемый язык браузера — RU или EN;
иначе используется английский. Ручной выбор имеет приоритет и сохраняется
в `clawlight-language` в localStorage, общем для главной страницы и руководства.
Чтобы вернуться к языку браузера, удалите этот ключ. Штатное языковое меню
руководства сохраняет текущую страницу и раздел. Небольшой мост
`guide/assets/language.js` сохраняет языковой выбор главной страницы;
`?lang=ru` / `?lang=en` позволяют ручному выбору работать и при заблокированном
хранилище. Без JavaScript текст и ссылки руководства остаются доступны
на языке его URL; запросы копируйте вручную. Демонстрация четырёх цветов
на главной странице по-прежнему использует обычные HTML/CSS.

Material обеспечивает адаптивную навигацию, локальный поиск и копирование
кода/запросов. Небольшой адаптер `copy.js` сохраняет кнопки Material и
использует Clipboard API с видимой и доступной обратной связью: удалось
скопировать или нужно сделать это вручную. Используются локальные системные
шрифты; внешние сервисы шрифтов и аналитика не настроены.

<a name="local-downloads-and-factual-limits"></a>

## Локальные скачивания и границы подтверждённых фактов

Маркеры `<!-- mac-downloads -->` и `<!-- model-download -->` в источниках
обоих языков раскрывает `pages.py`. Локальный просмотр использует новейший
полный архив Mac в `dist/`, рядом с которым есть `.sha256`. Он также даёт
прямую ссылку на `models/clawlight-print-pack.zip`, если архив существует,
с указанием открыть `START_HERE.md` / `START_HERE.ru.md` и английское или
русское руководство по печати. Если архива нет, руководство объясняет,
где найти инструкции печати в полной рабочей копии исходников. Архивы
не копируются в сайт. Без локального пакета Mac руководство ссылается
на сборку из исходников, поэтому чистая рабочая копия не требует
игнорируемых файлов `dist/`. Публичные сборки ссылаются на Releases этого
репозитория и архив исходников. Относительные пути учитывают оба языковых
маршрута. `BUILD.json` локального пакета указывает его архитектуру, дату
и исходники; локальный просмотр не пересобирает пакет. В пакет входят
полное руководство и настройка Codex; сайт содержит основные шаги и
самодостаточные запросы агенту.

Текст проверен по реализации, руководству по оборудованию и руководству
по печати; границы проекта уточнены 2026-09-18. Питание от USB Mac
поддерживается; отдельный блок питания и печатный корпус необязательны.
Прошивка в комплекте предназначена для ESP32-C3 SuperMini; другие чипы
этим пакетом не поддерживаются. `connected` означает, что служба записала
данные указанной лампе; это не доказывает работу LED или отправку хуков
Codex. Доставка событий настольного приложения требует проверки реальной
настольной задачей; облачные/удалённые задачи и обычные чаты ChatGPT
не управляют локальной службой.

Текущие физические результаты приёмки берите из руководства по оборудованию.
Сборка и тесты сайта не считаются проверками аппаратуры или установленной службы.

Изображения — наши CAD-рендеры, скопированные в `assets/`. Владелец одобрил
корпус и комплект печати как кандидата 1.0.0, готового к выпуску.
Финальная проверка физической сборки ещё идёт; рендеры и проверки сайта
не подтверждают посадку деталей. Источники изображений:

- `clawlight.png`: рендер `site/assets/clawlight.glb` с закреплённой версией model-viewer и камерой главного блока; показывает ту же геометрию, что и интерактивный просмотр.
- `assembly.png`: `models/clawlight/preview/flat_floor_exploded_20260918T101601Z.png`

Используйте только наши фотографии, снимки экрана, CAD-рендеры и геометрические
изображения. Фиксируйте здесь источник каждого материала и следуйте списку
медиа ниже.

Логотип и favicon руководства — наш простой SVG-светофор из трёх кругов
в `guide/assets/favicon.svg`; главная страница использует тот же геометрический
рисунок во встроенном favicon. Визуальные материалы продукта на сайте —
два указанных CAD-изображения и GLB, созданный из нашей CAD-модели.
Значки навигации, поиска и копирования Material — элементы интерфейса
лицензированной темы, а не изображения продукта. Сохраняйте лицензионные
уведомления темы и библиотек.

Для ещё не подготовленных фотографий и снимков экрана используйте
[список медиа](../docs/media.ru.md). Заменяйте рендеры только нашими проверенными
изображениями и точно указывайте, что является рендером, а что фотографией.
Публичное руководство также включает значки статуса, на которые ссылается
рабочая инструкция; они должны использовать собственное геометрическое
изображение лампы этого проекта.

<a name="publish-to-github-pages"></a>

## Публикация в GitHub Pages

Подготовленный [workflow Website](../.github/workflows/pages.yaml) публикует
главную страницу по адресу `https://OWNER.github.io/REPOSITORY/`, а руководство —
в `docs/` под ним. Русский маршрут — `docs/ru/`. Все локальные ссылки
навигации и пути ресурсов относительные, поэтому один артефакт работает
в корне домена, под префиксом репозитория или на собственном домене Pages.
Собственный домен задаётся в настройках Pages репозитория; переписывать URL
в исходниках не нужно. Ветка `gh-pages`, добавленный в коммиты сгенерированный
HTML и отдельный токен не требуются.

Когда всё готово:

1. Отправьте приложение, прошивку, документацию и исходники корпуса
   **в свой репозиторий**. Эти файлы, включая нашу CAD-модель, должны находиться
   в ветке по умолчанию для скачивания исходников. Перед публикацией следуйте
   [руководству по выпуску](../docs/releasing.ru.md).
2. В **Settings → Pages → Build and deployment → Source** выберите
   **GitHub Actions**. Если GitHub попросит, включите Actions в репозитории.
3. Откройте **Actions → Website → Run workflow** и выберите ветку по умолчанию.
   Дальнейшие изменения сайта или руководства по оборудованию в `main`
   публикуются автоматически. Если основная ветка называется иначе,
   измените `push.branches` в workflow.
4. Откройте URL из задания `deploy`. Если окружение `github-pages` требует
   подтверждения, одобрите развёртывание в GitHub. Разрешите ветку по умолчанию
   в правилах развёртывания этого окружения.

Pull request собирает и проверяет сайт без разрешений на развёртывание
и без публичного предварительного просмотра. Публиковать может только
ветка по умолчанию. Workflow использует
[стандартные действия Pages GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

<a name="downloads-live-in-github-releases"></a>

### Скачиваемые файлы находятся в GitHub Releases

Публичное руководство ссылается на **Releases этого репозитория**, используя
контекст репозитория workflow, а также на ZIP исходников и запрос агенту,
который поддерживает сборку из исходников. Для установки готового пакета
из руководства публикуйте полный комплект Mac/C3: архивы только с CLI
не содержат прошивку и руководство.

После проверки полных пакетов Mac публикуйте их вместе с соответствующими
`.sha256` по руководству выпуска. Корпус публикуйте отдельно как
`clawlight-enclosure-vVERSION.zip` с соответствующим `.zip.sha256`.
Кандидат 1.0.0 содержит комплект печати и руководство; в примечаниях
к выпуску укажите оставшиеся финальные физические проверки.

Сохраняйте исходное имя пакета, чтобы файл контрольной суммы продолжал
указывать правильный архив. Опишите поддерживаемые Mac/плату и оставшиеся
аппаратные проверки в примечаниях к выпуску. Сайт ссылается на список
релизов, поэтому публикация нового пакета не требует изменения сайта.
См. [документацию GitHub по ссылкам на релизы](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases).

Workflow выпуска создаёт полные комплекты Mac/C3 для Apple Silicon и Intel:
`clawlight-vVERSION-aarch64-apple-darwin.tar.gz` и
`clawlight-vVERSION-x86_64-apple-darwin.tar.gz`, каждый со своим `.sha256`.
Архивы CLI для Windows имеют отдельное имя `clawlight-cli-…` и не содержат
прошивку и рабочее руководство. Сайт явно указывает полные имена файлов
Mac; до первого полного выпуска предлагается сборка из исходников.
Руководство по сборке устройства указывает отдельные ZIP корпуса и контрольную
сумму, ссылается на руководство печати в репозитории и предлагает ZIP исходников
с CAD и STL как запасной вариант. Проверки и артефакты релиза описаны
в [руководстве по выпуску](../docs/releasing.ru.md). Сборка сайта не публикует
релиз приложения.

<a name="check-the-exact-pages-artifact-locally"></a>

### Локальная проверка точного артефакта Pages

Замените `OWNER/REPOSITORY` на репозиторий этого проекта. Доступ к GitHub
для сборки не нужен:

```bash
site/.venv/bin/python site/pages.py --repository OWNER/REPOSITORY
python3 site/check-links.py --site-dir site/_pages
python3 -m http.server 8081 --bind 127.0.0.1 --directory site/_pages
```

Откройте http://127.0.0.1:8081/. Игнорируемая папка `site/_pages/` содержит
только главную страницу, сгенерированную документацию и их ресурсы.
Workflow Pages загружает эту папку; файлы репозитория, Python-окружение
и локальные исполняемые файлы не публикуются. `pages.py` также содержит
небольшой хук MkDocs: публичные сборки заменяют локальные ссылки скачивания
ссылками на Releases и добавляют вариант с исходниками, а обычный локальный
просмотр сохраняет прямые ссылки на локальные архивы. Во включённых
руководствах ссылки на переводы остаются на сайте на выбранном языке.
Остальные ссылки на файлы репозитория в публичной сборке открывают GitHub,
а локально — пути рабочей копии. Маленькие значки трея встраиваются из
собственных изображений проекта в `assets/icons/`. GLB корпуса и метаданные
его происхождения входят в артефакт Pages; редактируемые CAD, файлы печати
и пакеты приложения — нет. Для обоих видов просмотра редактируются одни
и те же Markdown-страницы.

Сборка Pages читает оба языка из `docs/` и руководства печати, поэтому
запускайте её из полной рабочей копии. Проверены локальные сборки, HTTP-ссылки
в корне сайта и под префиксом репозитория, языковые проверки и копирование.
GitHub Actions, публичный адрес Pages и скачивание релизов требуют проверки
после публикации. Эта подготовка не создала репозиторий, релиз или публичный сайт.
