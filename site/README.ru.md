<a name="keep-the-instructions-in-sync"></a>

## Синхронизация инструкций

Полные публичные руководства находятся непосредственно в `guide/en/` и `guide/ru/`.
Краткие руководства включают именованные разделы локальной страницы оборудования,
например:

```text
--8<-- "site/guide/ru/hardware.md:lamp-wiring"
```

Сохраняйте маркеры `start:` / `end:` для `lamp-wiring`, `path-check` и `path-setup`
в обеих страницах оборудования. Команды, GPIO, номиналы резисторов,
поля протокола и явные ID заголовков должны соответствовать друг другу в переводах.

Каждый авторский документ проекта должен иметь версии EN/RU; лицензии зависимостей
сохраняйте дословно. При изменении поведения обновляйте затронутые сводки и запросы
агенту в `guide/en/` и `guide/ru/`. Перед коммитом выполните проверки ниже и сборку
Pages. Проверка переводов выявляет отсутствующие пары, якоря и источники нужного
языка; отсутствие раздела для включения останавливает сборку.

<a name="build-and-preview"></a>

## Сборка и предварительный просмотр

Выполняйте из **корня репозитория broglow** через [uv](https://docs.astral.sh/uv/getting-started/installation/).
В CI используется Python 3.14. Команды MkDocs используют закреплённую группу
зависимостей `docs` из `pyproject.toml`; `--only-group docs` ставит её без
инструментов прошивки.

```bash
uv run --frozen --only-group docs mkdocs build --strict -f site/mkdocs.yaml
uv run --no-project --python 3.14 python -m http.server 8080 --bind 127.0.0.1
```

Откройте http://127.0.0.1:8080/site/ для главной страницы и
http://127.0.0.1:8080/site/docs/ для руководства. После правок Markdown повторите
сборку; результат находится в игнорируемой `site/docs/`, главная страница не очищается.
Для сборки сайта не нужны сгенерированные STL, STEP/STP или ZIP и запуск CAD.
Эти результаты остаются игнорируемыми; файлы для печати публикуются в релизах.

Для автоматического обновления руководства используйте
`uv run --frozen --only-group docs mkdocs serve -f site/mkdocs.yaml`.
Он обслуживает только руководство; главную страницу и локальные скачивания
проверяйте через сервер из корня выше.

<a name="interactive-3d-and-ar"></a>

## Интерактивная 3D-модель и AR

В первом блоке постоянно показана основная фотография с тремя горящими светодиодами.
Сразу под ним раздел **«Посмотрите в 3D»** содержит просмотр собранной лампы
с эффектами сигналов и AR. В разделе сборки показана вращаемая 3D-сборка на том же
локальном model-viewer с `assets/assembly.glb`; она загружается лениво и поддерживает вращение
мышью и клавиатурой, масштабирование, сброс вида и повторную загрузку после ошибки.
Разнесённые детали открывают держатель светодиодов и точки крепления. Без JavaScript
основная фотография остаётся видимой, а 3D-просмотр показывает фотографию с зелёным
светодиодом.

3D-просмотр запускается автоматически с выбранным состоянием **Working**;
начальный постер — `assets/photos/signal-green.jpg`.
Локальные `@google/model-viewer` 4.3.1 и модуль эффектов используют общую Three.js
через локальную карту импортов (см. [vendor/README.ru.md](vendor/README.ru.md)). **Working**, **Paused**
и **Needs help** включают только зелёный, жёлтый или красный светодиод; **«Выключено»**
приглушает все три и убирает свечение. Умеренный ореол сохраняет цвет линзы.
Один точечный источник Three.js следует за активным светодиодом и подсвечивает
ближайшие поверхности его цветом с затуханием по расстоянию; **«Выключено»** отключает
источник. Он прикреплён через публичную выборку мешей композитора эффектов,
поэтому следует за моделью при вращении.

Выбранный сигнал применяется до первого кадра и после повторной загрузки;
сброс вида сохраняет его. Автоматическая загрузка не перехватывает фокус клавиатуры.
При ошибке фотография показывает выбранный сигнал и доступна кнопка
**«Загрузить 3D снова»**. Соответствие материалов экспортированному GLB проверяется
в `model-preview.test.cjs`. Android Scene Viewer заново загружает исходный GLB,
поэтому смена сигнала на него не влияет. Постобработка свечения недоступна
в AR-режимах, включая WebXR.

**«Примерить у себя»** открывает доступный с клавиатуры диалог с QR-кодом,
созданным локально, и ссылкой **«Открыть на этом устройстве»**. QR ведёт на текущий
путь сайта с `#view-in-space`, без параметров запроса: сканирование открывает
3D-просмотр, затем посетитель нажимает **«Поставить на стол»** для запуска AR.
Телефон использует собственные языковые настройки. В localhost/file-просмотре
вместо недоступного QR показана подсказка; для проверки сканирования и AR нужен
HTTPS-адрес, доступный телефону. При ошибке QR ссылка для текущего устройства
остаётся рабочей. Зафиксированная версия QR-библиотеки и лицензия — в `vendor/`.

AR использует `webxr`, `scene-viewer` и `quick-look` с `ar-scale="fixed"`; единицы
GLB — метры. Safari на iPhone/iPad создаёт USDZ по запросу (`ios-src` отсутствует);
другие браузеры iOS не проверены. WebXR требует HTTPS или loopback; телефон
не может обратиться к localhost другого устройства. Размещение и размер на
настоящих телефонах ещё требуют приёмки. См. [справочник AR компонента](https://modelviewer.dev/examples/augmentedreality/).

Модель показывает магнитный корпус из `models/magnetic/` с условными магнитами
и электроникой (`appearance.py` для просмотра собранной лампы, `exploded.py` для разнесённой
сборки). Для печати используйте отдельный пакет корпуса. Хеши исходников и
габариты находятся в `assets/broglow-model.json`; оба результата нужно
перегенерировать, а не править вручную. В полной рабочей копии запустите экспорт
с закреплённой группой зависимостей `cad`:

```bash
uv run --frozen --only-group cad python scripts/export-web-model.py
uv run --no-project --python 3.14 python scripts/export-web-model.py --check
uv run --frozen --only-group cad python scripts/export-web-model.py --exploded
uv run --no-project --python 3.14 python scripts/export-web-model.py --exploded --check
```

Для экспорта нужен CAD-скилл в `~/.agents/skills/cad` либо `--cad-skill /path/to/cad`.
`--check` использует только стандартную библиотеку и проверяет хеши исходников
и версию build123d из группы `cad` при наличии CAD; в сокращённых экспортах
сообщает о пропущенных сравнениях.
При добавлении сжатия Draco/KTX размещайте кодеки локально.

<a name="languages-and-behavior"></a>

## Языки и поведение

Лендинг по умолчанию английский, включая статический HTML и метаданные.
Русские переводы хранятся в атрибутах `data-ru`. Ручной выбор имеет приоритет
и хранится в общем ключе localStorage `broglow-language`; удалите его для
возврата к языку по умолчанию. Руководство использует язык URL, если его
не переопределяет сохранённый или явный выбор; `guide/assets/language.js`
сохраняет страницу/раздел и использует `?lang=ru` / `?lang=en` при
заблокированном хранилище. Язык браузера не меняет эти правила.
Без JavaScript ссылки работают на языке URL, запросы можно копировать вручную.

Карточки Open Graph и Twitter лендинга используют английский текст и нашу
фотографию лампы `assets/photos/broglow-all-lights.jpg` с тремя горящими светодиодами. Абсолютные канонический
URL и URL превью указывают на опубликованный сайт; `pages.py` адаптирует их
к значению `--repository`.

Значок GitHub рядом с кнопкой сборки ведёт в репозиторий и загружает число звёзд
и форков через публичный API GitHub. Без JavaScript или при ошибке запроса он
остаётся ссылкой на исходный код. `pages.py` адаптирует ссылку на репозиторий
к значению `--repository` и включает `github.js` в артефакт Pages.

Лендинг и руководство следуют цветовой схеме системы и предлагают переключатель
«как в системе / светлая / тёмная»: `theme.js` лендинга хранит выбор в ключе
localStorage `broglow-theme` и выставляет `data-theme` до первой отрисовки;
руководство использует трёхпозиционный переключатель палитры Material со своим
хранилищем.
Material предоставляет навигацию, локальный поиск и кнопки копирования;
`copy.js` добавляет доступную обратную связь об успехе или ошибке. Шрифты
системные; аналитика и внешние сервисы шрифтов не настроены.

<a name="local-downloads-and-factual-limits"></a>

## Локальные скачивания и границы подтверждённых фактов

Единственный архив корпуса — `broglow-models-vVERSION.zip`: папки
`stl/` и `step/` и `BUILD.json`; `printing.md` включает
его инструкцию из `models/magnetic/`.

`pages.py` раскрывает `<!-- mac-downloads -->` и `<!-- model-download -->`:
локальный просмотр ссылается на новейший полный архив Mac в `dist/` (с соседним
`.sha256`) и на `dist/enclosure/broglow-models-vVERSION.zip`, чья
контрольная сумма показана прямо на странице из соседнего `.sha256`. Без архивов
предлагаются инструкции для исходников. Публичная сборка ссылается на Releases и
ZIP исходников; сборка Pages запрашивает `.sha256` опубликованного архива из релиза
для текущей версии в `Cargo.toml` и показывает его на странице, а если сумму
получить не удалось, страница отсылает к странице релиза. Публикация
релиза перезапускает workflow Website на основной ветке, чтобы сумма попала на сайт. Автоматический ZIP исходников GitHub содержит
редактируемые исходники и инструкции, без STL, STEP/STP и готовых ZIP для печати;
скачайте комплект корпуса из релиза или [сгенерируйте его из исходников](../RELEASING.ru.md).
Просмотр не пересобирает и не копирует архивы; архитектура,
дата и исходники пакета указаны в его `BUILD.json`.

Неизвестные или отсутствующие ссылки на исходники во включённых инструкциях
останавливают сборку. Синхронизируйте процедуру генерации в
[руководстве по выпуску](../RELEASING.ru.md) с workflow релиза.

Поддерживаемое оборудование и проверки приёмки описаны в
[руководстве по аппаратуре](guide/ru/hardware.md). Тесты сайта и рендеры проверяют
отображение, а не физическую посадку или доставку событий агентов.

Источники наших изображений:

- `assets/photos/broglow-all-lights.jpg`: наша основная фотография лампы и оранжевого маскота с тремя горящими светодиодами, кадрирована 7:5 до 1400×1000; постоянно видна в первом блоке лендинга, используется в README и превью в соцсетях.
- `assets/photos/signal-green.jpg`: наша фотография с зелёным светодиодом, кадрирована 7:5 до 1400×1000; начальный постер 3D-просмотра и вариант без JavaScript, соответствующий состоянию **Working**.
- `assets/broglow.jpg`: наша фотография собранной лампы с выключенными светодиодами, кадрирована 7:5 до 1400×1000; используется для состояния **«Выключено»** в демонстрации сигналов.
- `assets/photos/`: наши фотографии собранной лампы (`state-*.jpg` — квадраты и `signal-*.jpg` — кадры 7:5 с одним горящим светодиодом, `inside-*.jpg` — вид сзади с держателем светодиодов и без него) и снимок окна приложения `popover-dark.png`, уменьшенные для сайта; оригиналы остаются неотслеживаемыми в `originals/`.
- `assets/assembly.glb`: разнесённая сборка из `models/magnetic/exploded.py`; хеши исходников и габариты — в `assets/assembly-model.json`.
- `guide/assets/favicon.svg`: наш рисунок лампы из трёх кругов, также используемый в favicon главной страницы. Значки трея берутся из `assets/icons/` в корне репозитория.

Следуйте [правилам медиа](../MEDIA.ru.md). Точно различайте
рендеры и фотографии; сохраняйте лицензионные уведомления темы и библиотек.

<a name="publish-to-github-pages"></a>

## Публикация в GitHub Pages

1. Следуйте [руководству по выпуску](../RELEASING.ru.md) и отправьте нужные
   исходники, включая CAD, в ветку по умолчанию своего репозитория.
2. Выберите **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Запустите **Actions → Website → Run workflow** для ветки по умолчанию.
4. Откройте URL задания `deploy`. При необходимости разрешите ветку по умолчанию
   и подтвердите развёртывание в окружении `github-pages`.

[Workflow Website](../.github/workflows/pages.yaml) публикует главную страницу
по адресу `https://OWNER.github.io/REPOSITORY/`, руководства — в `docs/` и `docs/ru/`.
Изменения в `master`, затрагивающие сайт, документацию, модели или другие пути из `push.paths` workflow, публикуются автоматически; для другой основной
ветки измените `push.branches`. PR проходят проверку без публикации. Свои домены
задаются в настройках Pages; относительные пути работают в корне домена и под
префиксом репозитория.

<a name="downloads-live-in-github-releases"></a>

### Скачиваемые файлы находятся в GitHub Releases

Публичные скачивания используют Releases этого репозитория с вариантом сборки
из исходников. Публикуйте полные комплекты Mac/C3 и отдельный ZIP корпуса
с контрольными суммами; архивы Windows содержат графическое приложение в трее и CLI,
но не содержат установщик, прошивку и руководства.
Имена файлов, проверки и порядок публикации — в [руководстве по выпуску](../RELEASING.ru.md).
Сохраняйте имена архивов и указывайте незавершённые физические проверки
в примечаниях к релизу.

<a name="check-the-exact-pages-artifact-locally"></a>

### Локальная проверка точного артефакта Pages

Замените `OWNER/REPOSITORY`; запускайте из полной рабочей копии. Доступ к GitHub не нужен:

```bash
uv run --frozen --only-group docs python site/pages.py --repository OWNER/REPOSITORY
uv run --no-project --python 3.14 python site/check-links.py --site-dir site/_pages
uv run --no-project --python 3.14 python -m http.server 8081 --bind 127.0.0.1 --directory site/_pages
```

Откройте http://127.0.0.1:8081/. Загружается только игнорируемая `site/_pages/`:
главная страница, собранная документация и ресурсы, включая GLB и файлы происхождения (provenance).
CAD, файлы печати, пакеты приложения и Python-окружение остаются вне артефакта.
Публичная сборка оставляет переведённые руководства на сайте, остальные ссылки
на исходники направляет в GitHub. После публикации проверьте GitHub Actions,
работающий сайт и скачивание релизов.
