# Сайт BroGlow DIY

[English](README.md) | [Русский](README.ru.md)

Главная страница в палитре Ember находится в `site/`. Она использует статические
HTML/CSS/JavaScript и тот же отрисовщик интерфейса, что и настольное приложение;
Vue, React, зависимости npm и отдельная сборка демо не нужны. Двуязычное
руководство использует [MkDocs](https://www.mkdocs.org/),
[Material](https://squidfunk.github.io/mkdocs-material/) и
[static-i18n](https://ultrabug.github.io/mkdocs-static-i18n/).

Прототип из `demos/homepage/` перенесён сюда как основная страница сайта.
[Контракт общего интерфейса](SHARED-UI.ru.md) объясняет границу приложения;
[исследование публичных исходников](REFERENCE-SOURCE.ru.md) сохраняет датированные
выводы о Blink Buddy. [Сравнение](comparison.html) и
[стенд размеров экрана](viewport-check.html) служат для локального ревью и не входят
в публикуемый артефакт Pages.

<a name="keep-the-instructions-in-sync"></a>

## Синхронизация инструкций

Полные публичные руководства находятся непосредственно в `guide/en/` и `guide/ru/`.
Краткие руководства включают именованные разделы локальной страницы оборудования,
например:

```text
--8<-- "site/guide/ru/hardware.md:lamp-wiring"
```

Сохраняйте маркеры `start:` / `end:` для `lamp-wiring`, `path-check` и `path-setup`
в обеих страницах оборудования. Команды, GPIO, номиналы резисторов,
поля протокола и явные ID заголовков должны соответствовать друг другу в переводах.

Каждый авторский документ проекта должен иметь версии EN/RU; лицензии зависимостей
сохраняйте дословно. При изменении поведения обновляйте затронутые сводки и запросы
агенту в `guide/en/` и `guide/ru/`. Перед коммитом выполните проверки ниже и сборку
Pages. Проверка переводов выявляет отсутствующие пары, якоря и источники нужного
языка; отсутствие раздела для включения останавливает сборку.

<a name="build-and-preview"></a>

## Сборка и предварительный просмотр

Выполняйте из **корня репозитория broglow** через [uv](https://docs.astral.sh/uv/getting-started/installation/).
В CI используется Python 3.14. Команды MkDocs используют закреплённую группу
зависимостей `docs` из `pyproject.toml`; `--only-group docs` ставит её без
инструментов прошивки.

```bash
uv run --frozen --only-group docs mkdocs build --strict -f site/mkdocs.yaml
uv run --no-project --python 3.14 python -m http.server 8080 --bind 127.0.0.1
```

Откройте http://127.0.0.1:8080/site/ для главной страницы и
http://127.0.0.1:8080/site/docs/ для руководства. После правок Markdown повторите
сборку; результат находится в игнорируемой `site/docs/`, главная страница не очищается.
Для сборки сайта не нужны сгенерированные STL, STEP/STP или ZIP и запуск CAD.
Эти результаты остаются игнорируемыми; комплекты печати на GitHub публикуются в релизах.

Для автоматического обновления руководства используйте
`uv run --frozen --only-group docs mkdocs serve -f site/mkdocs.yaml`.
Он обслуживает только руководство; главную страницу и локальные скачивания
проверяйте через сервер из корня выше.

<a name="interactive-3d-and-ar"></a>

## Интерактивная 3D-модель и AR

Страница прокручивается обычным образом. При прокрутке раздела с моделью
меняются камера и сигнал собранной лампы. Закреплённых сцен и привязки
прокрутки нет. Мышь и клавиши со стрелками поворачивают модель; **Working**,
**Paused** и **Needs you** выбирают зелёный, жёлтый и красный, а ползунок яркости
меняет силу свечения материала. Масштабирование отключено: колесо и вертикальные
жесты продолжают прокручивать страницу. Настройка уменьшенного движения отключает
программное движение камеры.

`lamp.js` использует локальный `@google/model-viewer` 4.3.1 с
`assets/broglow.glb`; Three.js разрешается через локальную карту импортов
(см. [vendor/README.ru.md](vendor/README.ru.md)). Индексы материалов светодиодов
проверяются по экспортированному GLB в `demo.test.cjs`. Пока модель загружается
или после ошибки показана настоящая фотография лампы; ошибка отключает элементы,
которым нужен 3D-просмотр. Фотография меняется вместе с выбранным сигналом и
сохраняет пропорции 7:5. Без JavaScript она остаётся видимой. Старого просмотра
разнесённой сборки на главной больше нет; инструкции печати и сборки остаются в
руководстве. `assets/assembly.glb` остаётся экспортируемым ресурсом.

**«Примерить у себя»** запускает нативный AR напрямую на поддерживаемых телефонах.
Другие браузеры открывают доступный с клавиатуры диалог с локально созданным
QR-кодом и ссылкой **«Открыть на этом устройстве»**. QR использует текущий путь
сайта с `#view-in-space` и выбранным `?lang=en` / `?lang=ru`, удаляя остальные
параметры. В localhost/file-просмотре недоступный QR скрыт, вместо него предложен
публичный просмотр. Для проверки передачи на телефон нужен доступный ему
HTTPS-адрес. При ошибке QR ссылка для текущего устройства остаётся рабочей.
Закреплённая версия QR-библиотеки и лицензия находятся в `vendor/`.

AR использует `webxr`, `scene-viewer` и `quick-look` с `ar-scale="fixed"`; единицы
GLB — метры. Safari на iPhone/iPad создаёт USDZ по запросу (`ios-src` отсутствует);
другие браузеры iOS не проверены. Во время AR изменения от прокрутки приостановлены.
Android Scene Viewer заново загружает исходный GLB, поэтому изменения материалов
в браузере на него не влияют. WebXR требует HTTPS или loopback; телефон не может
обратиться к localhost другого устройства. Размещение и размер на настоящих
телефонах ещё нужно проверить. См.
[справочник AR компонента](https://modelviewer.dev/examples/augmentedreality/).

Модель показывает магнитный корпус из `models/magnetic/` с условными магнитами
и электроникой (`appearance.py` для просмотра собранной лампы, `exploded.py` для разнесённой
сборки). Для печати используйте отдельный пакет корпуса. Хеши исходников и
габариты находятся в `assets/broglow-model.json`; оба результата нужно
перегенерировать, а не править вручную. В полной рабочей копии запустите экспорт
с закреплённой группой зависимостей `cad`:

```bash
uv run --frozen --only-group cad python scripts/export-web-model.py
uv run --no-project --python 3.14 python scripts/export-web-model.py --check
uv run --frozen --only-group cad python scripts/export-web-model.py --exploded
uv run --no-project --python 3.14 python scripts/export-web-model.py --exploded --check
```

Для экспорта нужен CAD-скилл в `~/.agents/skills/cad` либо `--cad-skill /path/to/cad`.
`--check` использует только стандартную библиотеку и проверяет хеши исходников
и версию build123d из группы `cad` при наличии CAD; в сокращённых экспортах
сообщает о пропущенных сравнениях.
При добавлении сжатия Draco/KTX размещайте кодеки локально.

## Превью для соцсетей

Проверенное изображение Open Graph и Twitter — PNG размером 1200 × 630 по пути
`assets/social/broglow-og-v1.png`. Оно объединяет одобренный портрет изделия из
собственной фотографии с удалением фона и очисткой деталей с помощью ИИ
и интерфейс выпускаемого приложения с тремя фиксированными примерами сессий.
На фотографии все три огня включены для демонстрации. Редактируемый макет,
одобренный вырезанный портрет и команда рендера хранятся в Git в `social/`.
Сборщик сайта упаковывает
проверенный PNG из `assets/social/`. Каталог исходников макета исключён из
публикуемого артефакта.

Обновляйте изображение после изменения дизайна, текста или соответствующего
интерфейса приложения. Запускайте из корня репозитория с Node.js 24 и Google
Chrome на macOS — одобренной среде рендера и системных шрифтов.

```bash
node site/social/render.cjs --output .recovery/social-preview/candidate.png
```

Параметр `--browser` выбирает исполняемый файл Chrome или Chromium. Команда
создаёт родительский каталог результата и требует новое имя выходного файла.
Она ждёт готовности шрифтов, изображений и фрагмента приложения, затем проверяет
результат 1200 × 630. Просмотрите кандидат в полном размере и при ширине 320px.
Сохраните одобренное изображение под новым версионным именем и обновите оба URL
социального изображения вместе. Поддерживайте точность отдельных EN/RU-описаний
`social.imageAlt` и добавляйте изображение с исходниками макета в один коммит.
Сборки релиза и сайта проверяют и копируют PNG из Git через обычную сборку
ресурсов сайта.

<a name="languages-and-behavior"></a>

## Языки и поведение

Лендинг по умолчанию английский, включая статический HTML и метаданные.
Словари EN/RU и привязки `data-i18n` находятся в `language.js`. Явный
`?lang=en` / `?lang=ru` важнее ключа localStorage `broglow-language`; затем идёт
сохранённый выбор, затем английский. Значок языка предлагает EN/RU и обновляет
текущий URL и ссылки на переведённые руководства. Руководство использует язык URL,
если его не переопределяет сохранённый или явный выбор; `guide/assets/language.js`
сохраняет страницу/раздел и параметры запроса при заблокированном хранилище.
Язык браузера не меняет эти правила. Без JavaScript ссылки и команды установки
работают на языке статической страницы.

Карточки Open Graph и Twitter используют проверенное английское
[социальное превью](#social-preview). Абсолютные канонический URL и URL превью
указывают на опубликованный сайт; `pages.py` адаптирует их к `--site-url` или
стандартному адресу GitHub Pages из `--repository`.
Метаданные в браузере следуют ручной смене языка; поисковые
роботы получают статический английский текст.

Первый блок демонстрирует мониторинг сессий настоящим отрисовщиком приложения
в изолированном iframe, разрешающем только скрипты, с примером состояния и
имитацией нативного хоста. Проверьте Working/Paused/Needs you, фокус терминала,
скрытие сессий и Settings. **Track usage** показывает пример квот Claude/Codex,
токены opencode и общую сумму токенов всех агентов. **Show usage in menu bar**
независимо управляет показателями строки меню. Имена, группировка, видимость
панели Dashboard, приоритет смешанных состояний и таймер возврата к чатам
используют общий отрисовщик. Настройки и скрытие сессий в демо остаются в памяти;
оно не читает реальные сессии, не устанавливает ПО и не управляет оборудованием.
Исходники и контракт хоста описаны в [SHARED-UI.ru.md](SHARED-UI.ru.md).

BroGlow работает ещё до сборки или получения лампы. Ссылки в шапке и блоке
установки ведут к инструкции; декоративные символы приглашения оболочки не
попадают в выделенные/скопированные команды Homebrew. Терминальную панель и
приложение строки меню можно использовать самостоятельно. FAQ также содержит
прямые ссылки на модели Printables и MakerWorld для желающих собрать лампу.

Ссылки GitHub в первом блоке и разделе исходников ведут в репозиторий.
`github.js` загружает число звёзд и форков через публичный API GitHub; ссылки
работают без JavaScript и при ошибке запроса. `pages.py` адаптирует ссылки
к `--repository`. Отдельная строка Releases/Issues/license удалена.

`theme.js` запускается до отрисовки, чтобы применить системную/светлую/тёмную
тему без вспышки. Он читает `?theme=auto|light|dark`, затем ключ localStorage
`broglow-theme`, затем системную схему; палитра бренда фиксирована — Ember.
В шапке значки языка и темы с доступными подписями и нативными списками выбора.
Остальные обычные скрипты используют `defer`; `lamp.js` — модуль. Руководство
использует трёхпозиционный переключатель палитры Material со своим хранилищем.
Material предоставляет навигацию, локальный поиск и кнопки копирования;
`copy.js` добавляет доступную обратную связь об успехе или ошибке. Шрифты
системные; аналитика и внешние сервисы шрифтов не настроены.

<a name="check-changes"></a>

## Проверка изменений

```bash
uv run --frozen --only-group docs python site/check-translations.py
node --test site/*.test.cjs
node --test tests/js/lamp-status.test.mjs tests/js/popover-library.test.mjs
uv run --frozen --only-group test pytest site/test_pages.py site/deploy/test_deploy.py
uv run --frozen --only-group docs mkdocs build --strict -f site/mkdocs.yaml
uv run --no-project --python 3.14 python site/check-links.py
uv run --no-project --python 3.14 python site/check-links.py --base-url http://127.0.0.1:8080/site/
```

Тесты проверяют границы общего интерфейса, настройки, учёт использования,
взаимодействие терминала и окон, локализацию, ресурсы, 3D/AR и социальные метаданные.
Проверка ссылок охватывает собранные страницы, якоря, языковые ссылки и скачивания.
Для HTTP-проверки оставьте сервер предварительного просмотра запущенным. Узкий
и настольный экраны проверяйте через `site/viewport-check.html`; эти проверки не
подтверждают работу установленных служб, установщиков, оборудования, AR на телефоне
или реального получения социальных превью.

<a name="local-downloads-and-factual-limits"></a>

## Локальные скачивания и границы подтверждённых фактов

Архив корпуса на GitHub описан в
[руководстве по выпуску](../RELEASING.ru.md#distribution); `printing.md` включает
его инструкцию из `models/magnetic/`.

Исходные страницы сборки и общие руководства по печати также ссылаются на
опубликованные модели на [Printables](https://www.printables.com/model/1884645) и
[MakerWorld](https://makerworld.com/models/3468773). Сохраняйте эти ссылки в
Markdown-исходниках рядом с автоматически добавляемыми вариантами загрузки с GitHub.

`pages.py` раскрывает `<!-- mac-downloads -->` и `<!-- model-download -->`:
локальный просмотр ссылается на новейший полный архив Mac в `dist/` (с соседним
`.sha256`) и на `dist/enclosure/broglow-models-vVERSION.zip`, чья
контрольная сумма берётся из соседнего `.sha256` и показана прямо на странице. Без архивов
предлагаются инструкции для исходников. Публичная сборка ссылается на Releases и
ZIP исходников; сборка Pages запрашивает `.sha256` опубликованного архива из релиза
для текущей версии в `Cargo.toml` и показывает его на странице, а если сумму
получить не удалось, страница отсылает к странице релиза. Публикация
релиза перезапускает workflow Website на основной ветке, чтобы сумма попала на сайт. Автоматический ZIP исходников GitHub содержит
редактируемые исходники и инструкции, без STL, STEP/STP и готовых ZIP для печати;
скачайте комплект корпуса из релиза, с одной из двух площадок моделей или
[сгенерируйте его из исходников](../RELEASING.ru.md#package-magnetic-enclosure).
Просмотр не пересобирает и не копирует архивы; архитектура,
дата и исходники пакета указаны в его `BUILD.json`.

Неизвестные или отсутствующие ссылки на исходники во включённых инструкциях
останавливают сборку. Синхронизируйте процедуру генерации
в руководстве по выпуску с workflow релиза.

Поддерживаемое оборудование и проверки приёмки описаны в
[руководстве по аппаратуре](guide/ru/hardware.md). Тесты сайта и рендеры проверяют
отображение, а не физическую посадку или доставку событий агентов.

Фотографии лендинга и 3D-файлы перечислены в [правилах медиа](../MEDIA.ru.md);
`photos/broglow-all-lights.jpg`, `photos/signal-green.jpg` и `broglow.jpg`
кадрированы 7:5 до 1400×1000. Другие источники изображений:

- `assets/photos/`: наши фотографии собранной лампы (`state-*.jpg` — квадраты и `signal-*.jpg` — кадры 7:5 с одним горящим светодиодом, `inside-*.jpg` — вид сзади с держателем светодиодов и без него) и снимок окна приложения `popover-dark.png`, уменьшенные для сайта; оригиналы остаются неотслеживаемыми в `originals/`.
- `guide/assets/favicon.svg`: наш рисунок лампы из трёх кругов, также используемый в favicon главной страницы. Значки трея берутся из `assets/icons/` в корне репозитория.

## Публикация в GitHub Pages

[Workflow Website](../.github/workflows/pages.yaml) публикует главную страницу
по адресу `https://broglow.mahenzon.ru/`, руководства — в `/docs/` и `/docs/ru/`.
Он собирает один артефакт `site/_pages/`, используя этот домен для рабочих
и канонических URL. Скачиваемые файлы находятся в GitHub Releases. См.
[распространение релиза](../RELEASING.ru.md#distribution).

Выполните шаги на сайтах GitHub и DNS-провайдера. Локальная авторизация
GitHub CLI необязательна.

1. Отправьте нужные исходники, включая workflow сайта, в `master`.
2. В **BroGlow/broglow → Settings → Pages** выберите **Build and deployment →
   Source → GitHub Actions**. Задайте **Custom domain** `broglow.mahenzon.ru`
   и нажмите **Save** до изменения DNS. На этом этапе проверка DNS ещё может ожидать.
3. В DNS-зоне `mahenzon.ru` замените прежние записи `A` и все `AAAA` для
   `broglow` записью `CNAME` с именем `broglow` и значением `broglow.github.io`.
   Введите только имя хоста, без схемы и пути `/broglow/`. Используйте режим
   DNS-only, если провайдер предлагает HTTP-проксирование.
4. Запустите **Actions → Website → Run workflow** для `master`. Откройте URL
   задания `deploy`. При необходимости разрешите `master` и подтвердите
   развёртывание в окружении `github-pages`.
5. Когда проверка DNS в Pages пройдёт и сертификат будет готов, включите
   **Settings → Pages → Enforce HTTPS**. Откройте `/`, `/docs/`, `/docs/ru/`
   и вложенную страницу руководства на своём домене. Проверьте поиск,
   переключение языков, скачивания, 3D-ресурсы, канонические и социальные
   метаданные, отсутствующий URL. Убедитесь, что
   `https://broglow.github.io/broglow/` перенаправляет на `https://broglow.mahenzon.ru/`.

Обновление DNS и выпуск сертификата могут задержать доступность при переносе.
Проверяйте прогресс в настройках Pages и включите HTTPS после готовности.
GitHub Pages обеспечивает перенаправление со стандартного адреса `github.io`
после настройки своего домена. DNS-запись `CNAME` направляет имя хоста в Pages.

Публикация через GitHub Actions использует настройку своего домена выше.
GitHub игнорирует файлы `CNAME` в артефакте Actions. Необязательная проверка
домена в **BroGlow organization → Settings → Pages** использует TXT-запись GitHub
для защиты от перехвата домена. Эта проверка выполняется отдельно от настройки
своего домена репозитория.

Изменения в `master`, затрагивающие сайт, документацию, модели или другие пути
из `push.paths` workflow, публикуются автоматически. PR и повторно используемые
проверки релизов с `check-only: true` выполняют проверки. Опубликованные релизы
запускают существующий workflow на ветке по умолчанию для обновления метаданных
скачиваемых файлов.

<a name="check-the-exact-pages-artifact-locally"></a>

### Локальная проверка точного артефакта Pages

Собирайте из полной рабочей копии с тем же публичным URL, что и CI.

```bash
uv run --frozen --only-group docs python site/pages.py --repository BroGlow/broglow --site-url https://broglow.mahenzon.ru/ --canonical-url https://broglow.mahenzon.ru/
uv run --no-project --python 3.14 python site/check-links.py --site-dir site/_pages
uv run --no-project --python 3.14 python -m http.server 8081 --bind 127.0.0.1 --directory site/_pages
```

Откройте http://127.0.0.1:8081/. Загружается только игнорируемая `site/_pages/`.
Она содержит главную страницу, собранную документацию и ресурсы, включая GLB,
файлы происхождения (provenance) и копии нативного интерфейса в `app-ui/`.
`site/pages.py` — единственный сборщик для публикации. Он заменяет исходные пути
`../assets/` на `app-ui/`, чтобы артефакт работал без репозитория.
`comparison.html`, `viewport-check.html`, тесты и Markdown для разработчиков
исключены. После правок лендинга или общего интерфейса повторите сборку. CAD,
файлы печати, пакеты приложения и Python-окружение остаются вне артефакта.
Публичная сборка оставляет переведённые руководства на сайте, остальные ссылки
на исходники направляет в GitHub. После публикации проверьте GitHub Actions,
работающий сайт и скачивание релизов.

## Перенос существующего домена с VPS

Следуйте шагам публикации выше, чтобы перенести `broglow.mahenzon.ru` в Pages.
Сохраните копию сайта на VPS до успешной проверки своего домена, HTTPS
и перенаправлений. Во время обновления DNS кеши ещё могут направлять посетителей
на VPS. Для отката переключения DNS восстановите прежние записи `A` и `AAAA`
для `broglow` из сохранённой конфигурации DNS-провайдера.

После слияния обновлённого workflow и проверки публикации в Pages удалите
настройки прежней публикации через веб-интерфейс репозитория на GitHub.

1. В **Settings → Secrets and variables → Actions → Variables** удалите
   `VPS_DEPLOY_ENABLED`, `VPS_HOST`, `VPS_USER` и `VPS_PORT`.
2. В **Settings → Environments** удалите прежнее окружение `vps` вместе с его
   секретами `VPS_SSH_KEY` и `VPS_KNOWN_HOSTS`. Если какой-либо из этих секретов
   хранился в **Actions → Secrets**, удалите его копию там.

Pages использует окружение `github-pages` и автоматический токен GitHub для
workflow. Удалите блок сайта BroGlow из Caddy и учётную запись публикации, когда
сохранённая копия на VPS перестанет быть нужна. Ограничьте очистку сервера
сайтом и учётной записью BroGlow.

Workflow Website публикует сайт только в GitHub Pages. Для отдельно
организованного ручного резервного размещения администратор может использовать
[блок Caddy](deploy/Caddyfile) и [помощник публикации](deploy/deploy.py),
собирая сайт в игнорируемый каталог `site/_vps/`.
